# M20: bounded floating-point foundation

Target: Linux amd64 SysV, QBE scalar `s`/`d`; assumes an IEEE binary32/binary64 host and the C numeric locale. This is a deliberately incomplete C floating-point implementation, not milestone approval.

Supported: `float` and `double` types, qualifiers, typedefs, pointers, arrays, record layout, `sizeof` and `alignof`; automatic storage, scalar loads/stores, same-type assignment, prototyped calls and returns, and indirect calls. Decimal and hexadecimal float/double literals (including `f`/`F`) are rounded using the host's `strtof`/`strtod` and encoded by their exact bit patterns. Literal overflow and underflow reported by the host are rejected. The spelling limit is 4096 bytes. Arithmetic `+ - * /` and comparisons require operands of the same floating type. Unary `+ - !`, conditions, short-circuit operators, comma, and same-type conditional values are supported. Negative zero is preserved by unary negation. Float-to-bool assignment/cast is not implemented; truth in conditions is supported.

Not supported: `long double`, `_Complex`, decimal floats, floating suffixes beyond `f`, digit separators in floating literals, float/integer or float/double conversions and mixed arithmetic, float increment/decrement and compound assignment, floating constant-expression evaluation, and nonzero static floating initializers (including nested aggregate writes). Floating expressions are not integer constant expressions. File-scope tentative objects and zero-filled aggregates use zero bytes. The preprocessor continues to require integer `#if` expressions. Variadic functions and aggregate ABI are outside this scope. Unsupported operations must be diagnosed rather than approximated. Host/target rounding modes and subnormal/exception behavior beyond what the host converter and QBE supply are not modeled; literal underflow is conservatively rejected.
