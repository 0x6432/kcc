# M11c: token pasting and placemarkers

## Decisions before implementation

Reference: WG14 N3096 6.10.4.1--6.10.4.4.

Implement ## and %:%: for object/function macros, including optional bodies and
stringized optional operands. Validate operator placement at definition time,
also within each optional body; failed definitions keep old bindings. Select
left-to-right operator evaluation as a documented choice where ISO leaves order
unspecified. Reject invalid concatenations rather than assume undefined behavior
will be useful. No GNU comma swallowing or named variadic extensions.

Only invocations whose definition contains ## need a materialized replacement
sequence. This is a bounded per-invocation list, not a translation-unit token
vector. Preserve the existing streaming path for other macros and its tested
whitespace policies. A new range builder substitutes parameters and performs #
and ## before ordinary rescan. Parameters adjacent to ## use raw arguments;
others use their existing isolated prescan cache. Multi-token arguments paste
only the adjacent boundary tokens. Generated ## tokens and ## tokens supplied
as arguments are ordinary tokens, never new operators.

Private argument-token records gain explicit operator/placemarker flags. Empty
arguments and absent/empty optional operands retain placemarkers until the right
operator phase. Paste resolves marker+marker to marker and marker+token to token;
real tokens concatenate spelling and re-lex as exactly one preprocessing token.
Keep markers across optional-range boundaries, remove them before ordinary
rescan or stringizing, and preserve meaningful separating whitespace. Ordinary
body names in #__VA_OPT__ remain unrescanned, including after inner pastes.

Reuse arena-owned prepared spelling views and the cumulative 1 MiB byte cap.
Never source_prepare generated concatenations: they are logical spelling bytes,
not physical input. Add count-only diagnostics (NULL stream) for quiet re-lex;
report one original-call-site diagnostic if lexing fails or finds zero/multiple
tokens, including attempted comment formation. Pasted pp numbers need not yet be
valid C constants; language conversion remains separate. Pasted hide sets use
the operand intersection, then inherit the invocation base during rescan.
Generated identifiers and keywords can now reach the parser, so all spelling
consumers/fuzz checks must honor non-input source ownership for any token kind.

All production operator code remains in preprocess.c. Bound active paste-range
builders at 32, alongside existing optional/prescan/frame/work/auxiliary limits.
Charge copied/intermediate nodes, range/operand visits and generated bytes;
allocation/resource errors latch invalid then EOF and unwind counters. Existing
public parser/AST/sema/QBE APIs stay unchanged. Optional # uses the range builder
only when its body contains ##; non-paste paths retain their prior behavior.

Test empty/multiple operands, two-level expansion, raw/no-prescan behavior,
rescan/hide sets, generated ##, digraphs, literals/pp numbers, invalid pastes,
optional/stringizing interactions and exact resource/error cleanup. Keep all
prior oracles/policy cases, add defined LF/CRLF/CR QBE programs and both fuzz seeds.
Validate GCC/Clang normal/sanitized, QBE/ABI, fuzz and exact-commit GitHub CI.
Push each tested checkpoint and continue into subsequent milestones without
waiting for user approval, unless a real blocker or interruption occurs.

## Following work

After macro operators: split conditional directives and include source ownership
into their own designed/tested checkpoints. Do not claim full preprocessing or
full C23 merely because the macro-operator milestone is complete. Preserve the
existing documented host whitespace/diagnostic interpretation gaps.
