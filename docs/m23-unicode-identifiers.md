# Unicode identifiers

Identifiers can contain UTF-8 source characters or fixed-width `\u` and `\U`
universal character names. KCC uses Unicode 15.1 XID_Start/XID_Continue and
requires the complete identifier to be in NFC. UCNs naming basic/control
characters remain prohibited in identifiers; the separate literal rules allow
those characters inside strings and character constants. Malformed UTF-8,
surrogates, out-of-range UCNs, forbidden characters and non-NFC spellings are
diagnosed. The Unicode tables are generated by
`scripts/generate_unicode_identifiers.py` with Python's Unicode 15.1 database.

Different spellings of the same scalar values name the same identifier, across
macro names and parameters, token pasting, scopes, typedefs, tags, members,
enumerators, labels, function and object symbols. Macro stringization preserves
source spelling; the resulting string has the corresponding UTF-8 characters.
`__func__` contains the decoded UTF-8 function name. Global and function names
are emitted as quoted QBE symbols with their UTF-8 ELF spellings, allowing
interoperation with native GCC on the supported Linux x86-64 target.

For bounded compilation, non-ASCII identifiers are limited to 4,096 scalar
values and 131,072 canonical-reordering steps. Quoted global/function symbols
are limited to 77 UTF-8 bytes because QBE 1.2 stores quoted definition names in
an 80-byte buffer. Local identifiers do not have this backend symbol limit.
These are implementation limits, not C23 limits. Unicode 15.1 support and the
compiler's other documented subset restrictions do not constitute complete
C23 conformance. C++-style delimited and named UCNs are not C23 syntax.
